# Phase 4 — 不可信文档处理威胁模型

范围：1.2.0 CLI 解析 PDF/DOCX/XLSX/PPTX/HTML/TXT/Markdown 与 XLSX 去重导出；边界为 WorkBuddy 对话/文件、用户授权目录、CLI 主进程、解析子进程、第三方库、临时目录和输出目录。假设攻击者可提供畸形文档、同用户/同机可写目录中并发改名换链，或诱导选择过宽目录；不假设平台提供未明确证实的容器、低权限身份或进程树约束。受保护资产：用户其他文件、隐私文本、宿主机可用性和输出完整性。内部实现与既有回归以 `reports/git-review.md` 为准；不是红队突破测试。

| 风险/来源与触发 | 影响范围 | 现有防护（源位置） | 剩余风险与分级 | 功能收窄能否缓解/发布判定 |
|---|---|---|---|---|
| **Windows CPU/内存限制**：特制 PDF/Office 令第三方解析无限分配/运算；`process_runner.py` 只在 POSIX 尝试 `RLIMIT_CPU/AS`。 | 同用户进程、整机可用性；可能拖垮 WorkBuddy。 | 60s 父进程壁钟、直接子进程 terminate/kill/join、32 MiB JSON IPC、文件大小预检。 | **高**：Windows 无 Job Object 或等价硬 CPU/内存约束，超时前峰值不可控；平台配额未知。 | 限小文件、可信输入可减小概率但不证明隔离。对公开任意上传 **阻断**。 |
| **Excel 主进程**：恶意 sharedStrings/极密表在 `load_workbook`、保存或重开验证阶段耗尽资源。 | 主 CLI、同用户 WorkBuddy/宿主机、输出。 | `spreadsheets.py` 使用 read_only/write_only、行 10 万/单元格 50 万/输出 50 MiB、两槽锁、迭代时间检查、临时输出清理及无覆盖发布。 | **高**：加载/保存阶段不受强制超时/内存限额；迭代检查不是进程级中断。 | **真正禁用** `deduplicate`、XLSX 检查及 `.xlsx` 通用 `parse` 路由可减少此类路径，但仍需解决其他解析器；当前未禁用，因此 **阻断不可信 XLSX 发布**。 |
| **后代进程**：第三方库/被利用解析器衍生进程或持有句柄；仅直接子进程回收。 | 孤儿 CPU/磁盘/文件句柄、后台读文件。 | `multiprocessing.spawn`；父进程超时 terminate、必要时 kill、join；异常关闭管道。 | **高**：没有 Windows Job Object/Unix 进程组 + 后代强制回收承诺；直接子进程测试不证明树清理。 | 仅处理可信输入可减概率；公开文件解析 **阻断**。 |
| **TOCTOU**：输入校验后，另一进程替换父目录 junction/symlink、同尺寸同时间戳原地修改；输出目录换链。 | 越权读其他同用户文件、意外写错位置/隐私外泄。 | `security.py` 检查根/符号链接、用 FD 对比 inode 并复制私有快照、重验 ZIP；输出同目录临时文件与原子无覆盖发布。 | **高**：路径解析各步与目录变更之间有窗口；Windows symlink 权限场景尚未实测。 | 独占、不可被敌对者修改的输入/输出目录是有效**运行前提**，但普通用户安装时平台是否保证未知；公开泛目录 **阻断**。 |
| **用户文件权限**：解析器进程继承用户身份，被利用后打开根目录外私密文件；广泛 `input_root` 亦扩大正常读取范围。 | 当前操作系统用户可读文件、可写目录；可能进一步访问网络。 | CLI 正常路径限制已授权根、快照、文件类型；Skill 要求明确选择文件。 | **严重**：路径校验只约束诚实代码，不约束被攻陷的解析器；Python venv 与 JSON IPC 都不改变 OS 权限。 | 单独低权限账号+只挂载明确输入/输出可缓解；当前实现没有，**阻断公开不可信文件解析**。 |
| **解析库漏洞**：PDFium/Office ZIP/XML/HTML/MarkItDown 等处理攻击载荷；或 zip bomb 绕过预检/高耗时解析。 | 用户权限内代码执行/文件读取或 DoS，可能影响本机。 | 白名单后缀/签名、Office 展开比/条数/大小检查、独立进程、POSIX rlimit、JSON IPC 32 MiB。 | **严重**：子进程非沙箱；关闭 pickle 只消除该 IPC 反序列化通路，未证明库安全。 | 移除特定高风险格式必须同步阻断代码路由、CLI、Skill、市场描述、发布说明和真实回归；本轮**没有**禁用任何格式，不能宣布格式级安全 MVP。 |
| **并发/DoS**：多个 CLI 进程/不同用户/重复重试叠加内存与 CPU。 | 单机/多用户主机可用性。 | `resource_slots.py` 同账户同临时目录 OS 文件锁最多两个槽，第三个明确 `RESOURCE_BUSY`；批次数量和总字节限制。 | **中高**：无跨用户/跨机器配额、无队列，单槽仍可超限；临时目录锁也是同用户可干扰资源。 | 运维层总并发、CPU/内存限额和速率上限可缓解；现时公共多租户 **阻断**。 |
| **临时/附件泄露**：异常退出、平台缓存保留或模型上下文接收正文。 | 文档隐私、磁盘残留和聊天接收方。 | 私有快照上下文清理、输出失败清理、Skill 不主动向第三方上传原文件。 | **中高**：SIGKILL 后残留、WorkBuddy 聊天/模型/附件路径未知；“本地处理”不可推断模型完全本地。 | 仅无敏数据、明确授权与短保留可缓解，仍需真实数据流/清理核验。 |

当前证据是代码审阅、历史 Windows 31 passed/1 skipped、Linux 32 passed 和 16 项轮验（`reports/git-review.md`），不是 Phase 4 新敌对负载测试。macOS 未实测，Windows 符号链接未实测。所有风险仅通过受控可信输入+低权限隔离+平台实际能力确认后才能重新评级；**现有 CLI 的 `SECURITY_PASS=BLOCKED`，不能以一项软限制升级为 PASS**。
