# Phase 4 — 运行架构决策记录

目标是不在未经授权的情况下部署服务或将 Python venv/普通子进程冒称安全沙箱。依据 [WorkBuddy Connector 规范](https://open.workbuddy.cn/docs/connector)：CLI+Skill 面向成熟跨平台 CLI，WorkBuddy 托管 Python 及隔离 pip 安装目录（5.0.0 起）；MCP+Skill 对网络 API 优先，远程端点需 HTTPS。**这些规范未承诺任一业务解析器有 OS 隔离。**

| 方案 | 安全性/未解决项 | WorkBuddy 文档与实测状态 | 普通用户安装成本 | 服务器成本 | 个人开发者维护成本 |
|---|---|---|---|---|---|
| A. 当前本地受限进程 + CLI | 只限制直接子进程超时、POSIX 部分 rlimit、JSON IPC、两槽并发；同用户权限、Windows 资源、Excel 主进程和后代风险依旧。**非安全沙箱**。 | CLI+Skill 包格式有官方文档；托管 Python 有文档支持。实际安装、命令业务宿主和执行权限 **UNKNOWN**。 | 若包已公开且依赖可达，理论可由平台管理 Python；现在包不存在，且 macOS 未实测。 | 无自建服务；宿主资源和用户风险转嫁不可视为零成本。 | 包/依赖维护低于服务，但跨三 OS 安全和支持成本高。 |
| B. 本地 OS 级低权限隔离（专用身份、受控目录、CPU/内存及整树收割） | **实现且实测后**可压低资源/权限/后代风险；Windows Job Object+限制身份、Linux cgroup/namespace、macOS 对应原生边界须分别设计，不把 Linux Docker 代替 macOS。 | 文档不说明 CLI 可创建/使用此类隔离、提权限制或挂载能力，平台兼容性 **UNKNOWN**；当前产品未实现。 | 可能要求操作系统授权、额外运行时/容器，普通用户一键安装未证实。 | 无远程服务器，但用户计算资源及各平台维护显著。 | 三 OS 隔离实现、升级、回归、客服成本**高**。 |
| C. 远程容器化处理服务 + MCP | 按租户鉴权、只挂载输入、独立 CPU/内存/时间/网络策略可缩小本机风险；服务器承受攻击，并引入上传敏感文件、存储/删除、滥用和合规责任；容器本身也非零风险。 | 官方推荐网络 API 用 MCP+Skill、远端 HTTPS；认证、传输与数据治理仍需落地和验证，**没有已部署服务**。 | 用户不必本地装 wheel，但需明确授权上传/账号或无账号限制；不可将用户文件暗中上传。 | 容器计算、存储、带宽、监控、备份有持续成本。 | 多租户隔离、法务/隐私、运营响应成本**最高**。 |

## 决议

**当前发布决策：暂停公开的文件解析 CLI Connector 发布**，保持 1.2.0 架构和全部能力仅作受控研发/私有验证候选，不改成新架构、不未经批准部署 C。对确需向普通用户提供不可信文件解析的**推荐目标架构是 B：在 WorkBuddy 允许的前提下，本地专用低权限 OS 级隔离，所有 PDF/Office 及 Excel 读写置于相同硬资源/整树边界**；若 B 的平台权限或跨平台成本不可满足，应重新取得隐私与运维授权再评估 C，而不是以 A 冒充已安全上线。A 可用于用户明知风险的、非敏感且来源可信文件的本地研发验证，**不等于市场可发布 MVP**。

B 的放行条件：明确 CLI 运行主机和账号/权限；各 OS 限额、整树终止及文件系统/网络最小授权的设计与真实运行；Excel 整个加载/写出受同一边界；敌对目录 TOCTOU 和资源回归；macOS 真机；可信 wheel 分发及 WorkBuddy 私有 E2E。只有运行前提和证据都满足才重新评审威胁模型。纯提示词产品的备选见 `phase4-mvp-scope.md`，不要求本轮重构解析架构。
