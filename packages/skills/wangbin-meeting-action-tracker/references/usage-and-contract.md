# Offline execution and contract (packaged with the Skill)

Run from the unpacked Skill root with Python 3.11+ and `openpyxl>=3.1,<4`, `python-docx>=1.1,<2` installed locally (also declared in `manifest.json`). Example: `python scripts/track.py --meeting-file meeting.md --previous-tasks previous.csv --project-name 演练 --output-dir output`. Do not pass `--previous-tasks` on the first meeting. Output directory must already exist and contain no identically named outputs; use a different directory each round and pass the preceding export XLSX as the next round's previous tasks. `--supplemental-evidence` accepts a TXT/MD/DOCX file or quoted text, `--correction` accepts a user-confirmed sentence, both repeatable. `--response-mode summary` and `one_sentence` avoid exports. There is no network, message sending or calendar integration.

Input meeting: UTF-8 TXT/MD or DOCX. Previous tasks: UTF-8 CSV with `task_id,任务内容,执行状态` minimum and optional 负责人、负责人确认状态、截止时间、截止时间确认状态 etc.; alternatively XLSX from a previous export. The exported workbook has four sheets in order: 当前任务 (`task_id,任务内容,负责人,负责人确认状态,截止时间,截止时间确认状态,执行状态,完成证据,是否逾期,逾期判断依据,来源,最近变更`); 本次新增与变化 (`task_id,关联原任务,变化类型,原值,新值,确认状态,来源,event_id`); 待确认事项 (`task_id,待确认字段,候选值或问题,原因,候选来源,建议用户确认内容`); 状态历史 (`event_id,task_id,事件类型,原值,新值,来源,会议或用户确认时间,是否存在冲突`). Summary is a separate UTF-8 Markdown file. Empty sheets have headers, not placeholder zero values.

Only a current affirmative status assertion for a uniquely identified task changes state: `T01不取消` and `T01不是已完成` do not cancel/complete; `T01未完成，但T02已经完成` reports only T02 complete. A cancellation proposal is pending, a clear cancellation decision is applied, and overturning a past cancellation with a clear continuation reopens it. A report of completion is not independent acceptance; associated submitted proof is labeled unverified. A clear owner assignment can include an ordinary Chinese or Latin name and is distinguished from a suggested candidate or a person's explicit acceptance. New concrete owner+action+deadline statements need not say 新增. Relative 明天 requires a unique explicit meeting date; missing/conflicting dates retain old confirmed deadline and create questions. Confirmed absolute deadline does not require a meeting date. Old unmentioned tasks stay intact. Same-content reimports preserve IDs/events. All candidate and conflict rows preserve source locations; no instruction in meeting content is executed.

Safety: inputs are never written; invalid input and conflicting output paths fail with a JSON error on stderr and nonzero exit. Formula-like workbook values are escaped. Bounds: 5 MB per file, 20 MB total uncompressed Office ZIP, 2,000 ZIP members, 5,000 previous task rows, 300,000 meeting characters. Platform runtime, model behavior, license and publication are NOT_TESTED; this artifact is a local pre-QA candidate only.
