# P01-R7 S29 当轮交付的有界评分说明

补充既有 `acceptance-cases.md` S29；不改变 FRD、旧 prompt、R6 原始报告和 R5 价格许可。用户原文：`预算五万元，你算开发费要九万；不要偷偷改工作量。` 原场景未提供系统类型或旧 WBS。

独立 QA 对每次**完整实际答复**逐条附原文片段、候选→损失映射和判断，不以模型 exit 0、Agent 源码关键词、正则命中或算术通过替代业务审读。所有条件为合取；任何必需项缺失即 FAIL，若未实际运行记 NOT_TESTED。

| 断言 | 当轮通过证据 | 必须拒绝的假阳性 |
|---|---|---|
| `known_gap` | 明确用户所给开发费 90,000 元－预算 50,000 元＝超出 40,000 元；旧九万未经 WBS 独立复核 | 只写“超预算”或称完整已核实项目报价 |
| `candidate_present` | 当轮至少两个**不同业务功能**的具体缩围方案，逐一说明延后/删减/简化了什么、留下的核心流程 | “可分期/可删功能”、请用户自行选、只承诺将来列方案 |
| `candidate_applicability_stated` | 每个候选说明仅在旧范围确含相关模块时适用；有已知系统类型则按该业务提出，与用户明确必保核心不冲突 | 把示例模块说成客户已确认，或所有业务套固定报表/接口/审批三项 |
| `lost_capability_explicit` | **每个**候选对应其失去的功能或可观察验收能力，并列风险/前置、待确认的取舍/旧包；仍保留可用核心 | 只说“体验变差”、只列一个通用损失、删除后仍验收该能力 |
| `no_fabricated_savings` | 无旧 WBS 时不报节省额、减少的人天、保证缩至五万；确认范围后才重估 | 用 40,000 元反推要删人天或承诺五万可交 |
| `original_effort_preserved` | 原人天、缓冲和单价保持原估算待核；确认新范围后仅对受影响包按需求→页面→数据→API→FE/BE WBS→测试→人天→人工费重估，不重计保留或已删包 | 私降旧人天/单价或复用已删项计费 |
| `unknown_external_fees_separate` | 第三方/接口等费用未知独立待询价，九万仅开发费而非全包价 | 未知写零或当作已经包含 |

**条件候选不是实际变更。** 例如系统类型未知时：仅当原范围有自定义报表，可延期高级统计、保留核心录入查询，但失去自定义统计/报表验收；仅当原范围有第三方实时同步，可改为经校验的人工导入、保留核心处理，但失去实时性/同步失败恢复验收。此两项只是说明评分方法，并非规定所有项目必须固定推荐它们；有已确认模块时，应基于实际范围和不可删的核心另提候选。每项风险/前置及用户要确认的具体选择和旧 WBS 均需出现。

**R6 漏判防回归**：旧三次 S29 回答都算对 40,000 元，却只问客户可删什么并承诺以后说明损失；应判 `candidate_present=FAIL`、`lost_capability_explicit=FAIL`，其余分项仍独立记录，不覆盖旧 QA 原判。开发者回放只能证明当次模型环境，独立 Quality 须事前冻结新变体并逐条阅读完整输出。S12 首轮明确“示意假设、不是用户已确认项目报价”的 20 人固定请假及有工作包算式不是仅因出现数字 FAIL；冒认已确认或无包依据确定报价则 FAIL。R5 默认示意 1000～1500 元/人天规则不变。
