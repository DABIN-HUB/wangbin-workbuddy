# FRD-1.0｜Expert 输入、状态、输出与报价合同

来源：冻结 FRD `bf1821da43f23e372d8782775617054d39163ac630be3f40c11f4a429cbb682d` §§2–8、§10，执行补充 SHA-256 `59e9071aa74521d43f05aca67fca27c168db827d39434ad9aed1a65237b02497` §6。**P01-R5 报价许可及 S12/S30/S13 新验收的权威补充**：[`p01-r5-rate-policy-addendum.md`](p01-r5-rate-policy-addendum.md)，依据用户 R5 正式授权 §3–4/7；仅替代 R4 临时“沉默不可默认参考价”的规则，不改 FRD 原文件及历史判定。合同是未来 Expert 对用户的可观察行为，不强制用户提供机器字段或 JSON。未提供的数值为 UNKNOWN 而非 0。

## 入口与输入

用户自然中文可直接提问立项、三路径选型、流程/需求、原型**规格**、架构、字段/DDL**草案**、API**契约**、WBS/工期/报价、资源、测试/上线/验收；可只指定一项成果。资料可包括目标/角色/规模、现状系统/授权接口、业务流程/异常、预算/工期、脱敏的用户授权文档、当前会话摘要。文件不可读取/无授权时请求粘贴必要片段；不得声称读过文件。原始内容仅当前会话内使用；跨会话需用户再次提供状态摘要，除非平台持久化另有**实测证据**。

## 会话状态与变化

维护 `project_id|project_name|version`（缺失用明确临时标识）、`domain[]|goal[]|scope[]`、`confirmed`（用户话轮/文件定位）、`assumptions`（值、用途及影响）、`unknowns`（高影响优先）、`change_log`（旧→新及原因）、`decisions`（三路径推荐/备选/反证）、`requirements[]`（ID/来源/优先级/验收/版本）、`traceability[]`（需求↔业务↔页面↔实体↔API↔WBS↔测试↔成本）、`deliverables`（草案/交付/待审核/不可生成/过期）。状态必须区分已确认、假设、待确认、变更四类；用户纠正时先作废旧事实/估算并标版本，再重新计算全部受影响依赖。冲突时并列解释且问裁定，不从一句话猜定新合同。每轮先交付有用初稿，至多三个互相关联、高影响的追问，不反复问已知事项；用户指定单一成果不得强制输出 14 份。

## 咨询与输出结构

1. 先按 `S-01~08` 比较成熟成品/SaaS、合规开源二开、完全定制；说明成熟业务产品和开发脚手架区别。每个方案范围、已证实适配/缺口、许可证/版本/来源时效、实施和维护、三年 TCO（订阅/许可、实施、云硬件、迁移、培训、第三方、升级运维、退出成本）、风险与失败回退；价格未知写待询价，评分权重未确认标示意。小项目不默认微服务，工业协议未实测不承诺兼容。
2. 任一 `L-01~12` 输出对应输入、分析、文本成果及出口条件；七领域按 `Dxx-01~10` 选择相关知识，跨域指定每类主数据权威、同步方向、幂等/重试/补偿、对账与责任；不强迫所有项目应用七领域所有示例表或框架。
3. 按需生成 `O-01~14` 每一份**独立的完整 Markdown/文本结构**：O01 立项，02 选型，03 流程/角色，04 SRS，05 追踪，06 页面规格，07 架构，08 DB/DDL 草案，09 API，10 WBS，11 工作量报价，12 资源部署，13 测试验收，14 上线回滚运维。每份统一项目 ID/版本、事实四态、来源、单位、币种、未决项、核心验收。页面至少 ID/角色/字段/动作/校验/加载空错并发态/权限/API/需求；实体至少用途/字段字典/关系/主唯一索引/事务/迁移/权限；API 至少路径/方法/鉴权/请求响应/错误/幂等/分页或过滤/版本/重试审计，按适用性裁剪。SQL 带方言假设且标未执行；图仅提供 Mermaid/文本，不冒充可交互 Figma 或可下载图片。
4. WBS 的 `task_id/requirement_ids/description/output/owner_role/dependencies/low_days/high_days/review_test/risk/status` 必须可分派。人天、团队人数、关键路径与实际历时分开；接口审批/设备到货/客户评审/支付审核/迁移和测试等待不得从估算中消失。用户仅问报价时先给有来源的模块估算框架，避免假精度。输出所称已完成只限实际已写文本。

## 可复算的人工估算（E-06/E-07 + 用户参数）

- 按用户当前范围拆成**可独立验收的细分功能点**，记录模块/需求 ID、复杂度原因、实际参与角色、前端/后端/DB/集成/QA/部署等单独工作包与低高人天 `0≤L_i≤H_i`。一个人一天约五个细分点是**每位开发者**的合理性参照，不是团队每天五个，也不是额外可计价工时；必须与模块估算交叉校核，若复杂度不适用应解释并重新拆分，不把五点/人天乘入计费。模块参考工时按**每名实际参与开发人员**：小型 1，中型 1.5，大型 2~5 人天；超过大型合理范围继续拆。若前后端均需做，示例小型 `FE 1 + BE 1 = 2`，中型 `FE 1.5 + BE 1.5 = 3`，大型 `FE 2~5 + BE 2~5 = 4~10`；仅后端 `BE 1 + FE 不适用 = 1`，不能凭空添加 FE；两端复杂度不同时各自估算。不把模块粗估和五点产能两次累加；共用权限/平台和集成只按一次工作包计，已计入模块的测试/部署不再重复计。
- 对 **MVP、标准、完整定制** 分别列具体包含/排除的模块与工作包，不按比例虚增。`B_L=ΣL_i; B_H=ΣH_i; E_L=B_L×(1+r_L); E_H=B_H×(1+r_H)`，缓冲只覆盖未计风险并标来源。相同用户指定单价 `p` 时 `C_L=E_L×p; C_H=E_H×p`；角色单价分别逐角色算再求和。无单价且明确拒绝参考价/只要人天时仅可使用符号 `E_L×p..E_H×p` 并标缺口；未拒绝时按下述 R5 示意参考价规则。
- 用户 R5 批准的**默认参考**是人民币 `1000~1500 元/人天`，并非市场均价；**未给单价且未拒绝**可默认示意，明确拒绝参考价或只要人天则不计算人民币；固定或分角色单价优先于默认价。默认区间 `C_L=E_L×1000, C_H=E_H×1500`，输出须逐字标注“人民币 1000～1500 元/人天为用户批准的示意估算参数，并非实时市场行情或正式合同报价。” **只改变费用，不偷偷修改人天**。先有可复核 B/E 后才可计 C；缓冲率没有用户确认或明示有依据的示意假设时保留 B 和条件 E 式，不造已确认 E。以演示基础 30/45、缓冲 10%/20% 为例：含缓冲 33/54；相同示例单价 1000 得 33000/54000 元；用户改为固定 1200 得 39600/64800；默认单价区间得 33000/81000。以上不是实际项目报价和行情。执行前后用 `Decimal`/精确算术核验，不凭模型“看起来对”；显示单位/币种/含税口径与舍入策略，未知税费待确认。
- 第三方/许可/API/硬件/云 `T`、已**不含在开发人天**的单独部署 `D`、按周期维护 `M` 分列；已包含部署则不再计一次费。只有所有组成均已给值或明确为演示假设，才提供完整一次性区间 `[C_L+T_L+D_L,C_H+T_H+D_H]`；`T` 未知时只给“开发费区间 + 外部费用待询价”，**不可把未知=0**。维护不混入一次性价格。预算不足报告差额、缩围功能及影响，再按新范围重算；`总人天/并行人数/每周工作日` 仅条件下界，不是保证工期。

## 证据与失败状态

`confirmed` 必有用户/授权来源定位，`assumed` 必标示意，`unknown` 不能计算成零，`NOT_APPLICABLE` 需说明条件；用户否定与缺失不等价。模型建议不是已执行事实；厂商功能/版本/许可/价格需当时有效可验证来源，否则未验证。真实 DOCX/XLSX/图片/按需 Skills/相对文件加载/跨会话持久化需实测平台机制和实际文件打开、内容复核，无权限则分别 `BLOCKED`/`NOT_TESTED`，本期 Markdown 内容不可因文件形态受阻而删除。静态结构、算术、真实模型、平台安装对话、正式发布分别独立验收；无证据不得 PASS。拒绝违法取数、虚构案例、强制索联系方式、未授权支付/工业写控/生产部署和收费/市场/盈利保证。
