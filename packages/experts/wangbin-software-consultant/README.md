## 使用与限制

在当前会话基于用户授权的脱敏文字澄清需求、选型、设计、报价、交付文本和验收计划；没有客户生产数据库、支付、设备、后台或跨会话持久化。报价按受控范围/工作包及已批准的示意参数计算，外部未知费待询价，不冒充市场行情或正式合同。自然语言交互不要求用户填写 JSON/CLI。案例/测试留在源码目录且不入 ZIP；1.0.0～1.1.2 及 1.2.0 为历史版本身份，不以旧 ZIP 代表 1.2.1。1.2.0 第八批独立真实模型首次代表试验为 1 PASS/2 FAIL，非 WorkBuddy 原生验收；1.2.1 仅修订三问语义门槛、变更成果实质覆盖及映射/CR 与成本状态核对，保持包内 Skill 0.2.0 和计算合同 2.0；当前新源码的真实模型、本地回归及候选归档验收尚未执行，不继承旧版 PASS。第四批计算合同 2.0 和有限本地合成核验证据见需求盘点 §10；第五批 Q32～Q34 确认本地工程交付。实际候选身份、构建状态及核验结果以对应 manifest、SHA-256、catalog 和需求盘点 §11 的真实证据为准：源码提交、ZIP、逐成员字节与分发版本须绑定，不以 README 文字代替归档证据。不覆盖历史候选；不宣称已安装、审核、收费或发布。

本包不运行独立后台、MCP、数据库或外部 API；若平台授权包内 Skill，则可按现行技术合同对实际源值进行确定性人天、获准人工费及外费核算。未获授权时仅对话输出文本。平台解析、召唤和模型表现未经 WorkBuddy 真实验证。

## 用户能得到什么

- 用最多三项优先问题逐轮澄清目标、角色、人数、流程、接口、迁移、部署、预算与周期；即使用户暂不回答，也先提供有用的初稿。
- 输出已确认需求、假设和待确认事项；将功能拆到输入/处理/输出/异常、优先级、依赖、验收标准。
- 结合规模比较单体与复杂系统架构，工业协议先确认现场设备能力和网络/许可边界。
- 完整报价按 `MVP=M`、`StandardA=M∪S`、`StandardB=M∪S∪I`、`FullA=M∪S∪F`、`FullB=M∪S∪F∪I` 五档独立成员计算；I 仅为两个 B 档的实际接口实施条件增量。A/B 只有范围、费用事实/计价口径与适用条件均有证据且相同才合并摘要，详细档位不合并；单项估算不强制五档。包内计算合同 2.0 支持实际所求完整五档/指定档/局部，全部适用角色及唯一分派、低高及有据独立基准、各档有据缓冲、许可单价与分组外费；合法缺失返回有据小计及缺口，不填零或冒称完整。只要人天不报金额；多币种不换汇、不推税率，周期费用不重复加入一次性报价。旧无版本输入保留四角色兼容路径；只在实际有效回执覆盖的结构及算术上标核验，不认证客户真实范围、估时、人员排期或正式合同报价。
- 按需在对话里输出需求说明书、模块清单、分终端页面导航、技术方案、数据库与 API 草案、WBS/个人或条件排期、预算参考、验收/上线计划等 Markdown 文本；不是已生成可下载附件。已证实的资产复用才入基础估算，待核则列可比较的条件差量。
