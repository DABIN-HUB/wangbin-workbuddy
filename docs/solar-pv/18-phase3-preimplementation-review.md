## 4. D2：申请版本化计算方法/明确假设配置入口

### 4.1 为什么不能仅靠现有字段直接算

- resource.cell_temperature_c是281公式域中的变换状态，原始输入只有环境温度/风/型号/方法；没有温度子模型及其系数契约。STC温度常量在绑定中仍为null，不能凭常识填25°C，更不能令cell=ambient。
- finance.cashflow_timing、tax.vat_recovery_timing、finance.cfads_definition是字符串，不是可执行现金事件、税务/合同算法。
- finance.debt_schedule的本金/利息/费用是应付计划，不是已付金额或资本化未付利息。同一支持字段同时出现due/paid映射不证明二者相等。
- finance.working_capital是单个初始金额；不能每年再扣一次，也不能据此得出应收预收、应交预缴、股东出资/分配/退出全部余额。
- finance.irr_search_domain和sensitivity.price_search_domain存在于281域，但不在469输入ID中；不能伪造scenarios.options.changed_field_id，或把配置塞入无类型文本。
- 首年PR、初始衰减、分段/更换性能恢复存在多生产与覆盖选择；年度交付量简单按衰减缩放不一定保持限幅和负荷匹配，应明确方法而不是无条件套式。

### 4.2 推荐做法

新增单独版本且严格Schema化的**计算方法/数值策略/显式假设配置**，保留469原始字段和281域ID的含义，不让用户填86个未知账簿，也不把文本当代码执行。

配置至少包括：

1. 温度方法、设备/安装参数、STC定义依据和适用域；候选方案为有一手方法文档的模块温度→电池温度分步模型，系数逐项显式提供，不将网站代表值当全国默认。
2. 资源/运营/日历/现金时点，初始余额和预测收付规则；税务批次、抵扣/缴退及项目/权益税基；股东出资、受限分红、留存和退出规则。
3. 零息/等本/年金/到期/自定义计划的生成规则、日计数、事件顺序、宽限、付现/资本化分离及评价期末未偿处理。
4. IRR根隔离/重复根、允许域、容差/资源上限/穷尽性；盈亏电价允许域、指定价格项及整链重算策略。绝不选有利根。
5. 明确损失覆盖/顺序、首衰/后衰/更换恢复与代表性曲线映射规则，不由年总量伪造“真实小时曲线”。

全部新增方法参数或假设必须带单位、来源/依据和状态，执行前校验并纳入配置/来源/计算输入及结果摘要。原Phase2 input_hash/source_snapshot_id先严格重验并保留；若计算身份扩展，须显式定义组合关系和版本，不把未入hash的额外JSON作为旁路事实输入。真实材料不能被合成默认覆盖。

可先启用**明确标记SYNTHETIC的封闭预测配置**验证算法，例如明确声明新建项目期初余额、预测按期支付和分配假设；这些是测试输入，不是从缺失数据自动推零，更不默认适用于真实项目。实际项目缺证据时仍阻断。

**替代：**扩展原子输入目录承载新增事实，涉及Schema/基线版本/迁移/回归；或暂不闭合这些方法，核心链保持PARTIAL/BLOCKED。只实现简化年度PR或一个NPV函数，不能替代本轮完整要求。
