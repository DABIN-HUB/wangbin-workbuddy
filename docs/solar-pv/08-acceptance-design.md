# 可执行矩阵及验收设计

## 两层状态不得混淆

`08-requirement-traceability.csv` 的 `baseline_status=FROZEN` 只表示条款已逐项冻结；`status` 是产品实现/实测状态，尚未执行的功能仍为 `NOT_IMPLEMENTED`/`NOT_TESTED`。`test_id` 在 `08-acceptance-cases.json` 和 `08-derived-acceptance-cases.json` 的合并集合中有命名、阶段、类别、方法与通过条件；Phase1只冻结这些用例，不制造空函数或虚构数值通过。

原文每个非空非标题/围栏行都以源行号与条款全文追踪，18章再拆分子项；输入、公式、术语、分类与四文件逐条追加独立ID。原文包含的目录树/阶段协议亦保留，不从矩阵中删除。条款复合项的父行永久保留，细分子行可追加，不能只留下概括父行代替专项测试。

## 执行接口

- `python docs/solar-pv/verify_baseline.py`：只读文档契约核查。校验原文哈希/章节覆盖、必交付文档、矩阵ID/引用、输入/公式/术语索引、分类状态、测试定义与证据状态。输出JSON和退出码。文档PASS不推导产品实现PASS。
- `python docs/solar-pv/verify_baseline.py --release`：在同样检查后要求所有实现需求真实PASS及六种产品门禁PASS。当前必须非零返回BLOCKED。禁止把默认文档核查exit0作为发布合格。
- 后续数值/文件/平台用例必须绑定真实执行器及不可变证据（命令、输入hash、模型版本、日志/产物hash）；尚未开发的执行器保留PLANNED，不能当可运行测试。完成后按原test_id增加明确pytest节点或手工签核脚本/记录，而不是另造ID逃避旧失败。

## 数值验证协议（Phase3起）

每个公式注册表中的样例必须明确“虚构/独立参考/实测”身份，保存参考算法或手工推导、各变量单位/边界、容差的绝对量及相对量与选择依据。金额与电量分开容差，NaN/Inf不通过。不可无条件提高容差消除失败，不用同一引擎重算输出充当独立参考。迭代求根记录根区间、迭代次数/残差及唯一性分析；多根不得只返回扫描遇到的第一个根。输入/输出因果及守恒比字符串断言优先。

首个工业1MWp与地面独立虚构样例覆盖完整25年及用户指定年限；建设期多时点/现金税与折旧/债务现金流及设备更换必须参与。静态/动态回收期起点、插值与期内不回收、名义/实际税前/税后/LCOE交付电量边界有独立参考。

## 文档与四文件验证协议（Phase5起）

四个文件必须由同run的canonical JSON真实渲染并重开读取；以指标ID/表ID/行ID/单元格路径核对，不靠文件名或正文片段判一致。机器检查18章及13附录、公式符号/术语与数据索引闭合；DOCX可编辑且有域/页眉页脚/图表，PDF中文文本可检索；实际渲染后的封面、目录、跨页长表、公式/图表页与末页抽样视觉留痕。转换器缺失应真实失败并保留现成文件，不创建假PDF。工作簿明确静态计算快照或已验证重算缓存，空公式缓存不算数值。人工审阅与自动数值核对各留证据。

## 安全与环境协议

用受控本地虚构负载测试路径/符号链接/Office展开比/宏/链接/公式注入，不将真实用户商业资料作为公共fixture；扫描日志和证据仅显示脱敏ID。Windows符号链接等无权限只能SKIPPED，并保留对应环境未通过，不能免除跨平台/敌对输入验收。旧引擎已知高风险独立BLOCKED。任何远端副作用/付费API/发布须授权，离线fixture不能冒充真API。

## 六类产品门禁

1. DOCUMENT_COMPLETENESS：真实报告18章/附录/公式符号/术语/来源/四文件完整。
2. CALCULATION_CORRECTNESS：独立参考、数值边界、能量/现金/债务守恒和属性测试。
3. DATA_AUTHENTICITY：每个数据来源/时效/许可/地区/冲突和假设明确，真实与虚构隔离。
4. RUNTIME_COMPATIBILITY：实际操作系统、依赖、转换器/字体、安装和文件导出证据。
5. WORKBUDDY_INSTALL_CALL：真实平台候选的安装、召唤、Skill/Connector调用和文件回传。
6. PLATFORM_REVIEW：确切版本的官方审核回执；未经授权不提交。

每个项目分类单独维护这些状态。Phase0/1只关闭文档冻结与仓库审计工作；产品DOCUMENT_COMPLETENESS也不能因“文档需求齐全”标PASS。六类当前均NOT_TESTED，发布BLOCKED；另外记录许可/安全与隐私。
