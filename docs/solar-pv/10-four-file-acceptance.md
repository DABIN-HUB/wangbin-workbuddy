## 2. 统一canonical result与同源哈希

### 2.1 单一真源

所有章节、图表/附录、F03/F04只读同一带版本的 `canonical calculation result JSON`。其保存：类型/基座、成熟度/建议及原因、规范输入+全字段provenance、受控来源快照、分类/计算方法版本、情景、月/逐时/年度能量与财务明细、公式/符号/术语索引、风险缺口、claim定位、导出模式及五标识。不得在Word模板、图表脚本或LLM内另算/填不同值。

canonical JSON、manifest与证据为四文件之外的本地受控复核材料，不偷换四份交付，不默认公开原附件或含密JSON。哈希不是匿名化或授权，敏感信息及可链接摘要仍按权限保存。

| 标识 | 定义与变化边界 | 四文件落点 |
|---|---|---|
| `model_version` | 引擎/计算契约版本，schema/formula/category配置另有版本；变更不可沿用旧签核 | DOCX/PDF版本页与附表；两XLSX每sheet元信息 |
| `run_id` | 单次不可变运行ID；同输入重跑仍新run，禁止混装 | 四文件封面/首页及所有附表/sheet元信息 |
| `input_hash` | SHA-256摘要：规范输入、单位、被选来源/候选状态/处理规则及所用输入契约版本；目标、时区/粒度和情景也纳入 | 同上，完整摘要可读可复制 |
| `source_snapshot_id` | 来源manifest的内容寻址ID；数据集/文档摘要、版本、获取/有效时间、许可及适用性冻结，附件用受控ID | 同上，公共导出不含密路径 |
| `result_hash` | SHA-256摘要：确定性result_payload，含model/schema/formula/category版本、input_hash、source_snapshot_id、情景、输出/状态/边界 | 同上，与canonical结果一致 |

### 2.2 哈希前像与可重现性设计

- 将hash文档明确分成 `result_payload` 与 `run_metadata/export_metadata`。result_hash仅对result_payload计算，**排除result_hash自身、run_id、生成时间、输出文件字节哈希及渲染器非确定元数据**，避免自引用/每次都变。运行ID用于交付集绑定，不当数值可复现性证明。
- 计划规范化：键按Unicode码点排序，UTF-8无BOM，紧凑JSON；数组按业务语义稳定顺序（时序/年序/row_id）而非任意重排；布尔/null保留类型；只允许有限数，负零规范为0，数值按声明十进制精度转固定规范数值表示、不带分组符，不随操作系统locale变化。数值类型与文字类型不可碰撞；未冻结/实现同一数值序列化器之前不得声称跨语言哈希一致。
- input_hash前像不含input_hash自身、访问令牌/密钥、导出路径和不影响输入的显示时间；包含所有实际采用输入及状态、变换/版本、影响模型的目标/场景。source_snapshot_id对独立来源manifest计算；快照更新即新ID，不能原地替换后沿用旧标识。
- 文件SHA-256另在外部交付manifest逐个登记，并带F01..F04精确文件名、字节数、真实格式、生成/校验/视觉证据、canonical文件摘要；不能放入result_payload导致循环。可在未发布manifest先校验，再原子提交整集。
- 未来 `T-HASH-ORDER` 验证键顺序/locale不变结果，`T-HASH-NUMBER` 验证小数/负零/非法数，`T-HASH-CHANGE` 验证输入/来源/版本/场景变动相关hash失效，`T-HASH-CYCLE`验证无自引用，`T-HASH-MIX`拒绝不同run混装；均NOT_IMPLEMENTED。

### 2.3 全量与抽查一致性

机器全量核对canonical中全部被展示的结果/状态/单位、19+10sheet和claim定位；人工抽查关键数值与图形。不得只抽一两个摘要指标就声称全部一致。对首年/年均、12月、全期年度电量和现金流、DC/AC、投资/OPEX/税/债、NPV/IRR/回收期/LCOE/DSCR、自用售电限发、四态和成熟度做同边界比较。

整数/ID/月份/版本/hash与状态必须精确相等；内部十进制值按计算契约精度逐值等同。显示值以canonical已冻结的显示精度/舍入规则相等；金额/电量/百分率各有声明，不能把所有差异放宽成1%。未来数值参考校验分别声明绝对/相对容差及理由；校验报告保存实际差异与位置，不使用“看起来一致”。

## 7. XLSX可编辑、计算快照与重算边界

### 7.1 两种真实可声明模式

| 模式 | 合格条件 | 用户编辑后的行为 | 不合格反例 |
|---|---|---|---|
| `STATIC_SNAPSHOT` | 确定性引擎输出真实数值、输入/结果分区、公式文本/符号解释、五标识及“静态快照，Excel内不自动重算”醒目声明 | 输入单元可编辑用于另存/重新导入，但旧结果不自动有效；必须重新运行引擎新run生成四文件 | 有公式但缓存全空、把recalcOnLoad当已计算、假称改Excel可实时更新PDF |
| `VERIFIED_RECALCULABLE` | 指定真实Excel/LibreOffice等已验证重算器/版本；所用函数可支持；公式缓存实际有值且与canonical一致 | 在副本修改有效输入、真实重算、保存再读缓存；相关结果确实变化并与独立引擎一致；随后导入引擎生成新run/四文件 | openpyxl写公式后data_only=None却标已计算；仅设fullCalcOnLoad就PASS；无关硬编码结果 |

openpyxl本身不计算Excel公式；元信息/说明区声明模式及重算环境。STATIC_SNAPSHOT是允许的真实复核模式，不冒充动态财务模型。VERIFIED_RECALCULABLE是额外能力门禁，未验证就NOT_IMPLEMENTED。两模式都要求文档可编辑、输入来源可追溯、计算结果实际有数值或明确UNKNOWN，不能以模式声明容忍空缓存重要指标。

### 7.2 编辑与重新签核

- DOCX正文表格可编辑不等于编辑后PDF自动同步；XLSX输入可编辑不等于公式/引擎已自动重算。每份首部说明“修改后原五标识仅对应原始导出，原校验/签核失效，需新运行重新发布”。不提供未实现的宏/后台自动校验承诺。
- 文件字节摘要改变则读取端能检测与manifest不符。工作表保护仅防误改，不是加密、权限或完整性保障。原始交付集不可原地改写；副本/导入后生成新run，旧版本可追溯。
- 未来 `T-XLSX-EDIT` 修改输入保存再打开；`T-XLSX-RECALC` 比对变更前/后缓存与数值；`T-XLSX-SNAPSHOT`检查快照声明及必须重跑路径；`T-XLSX-ERRORS`扫描#REF!/#VALUE!/#DIV/0!/#NAME?等及无效外链；`T-XLSX-OPEN`在约定查看器真实打开并保存副本；均NOT_IMPLEMENTED。

## 9. 事务式生成、失败保留与原子发布

计划状态机：`CREATED -> STAGING -> CALCULATED -> RENDERED -> VALIDATED -> REVIEWED -> READY -> PUBLISHED`。任一步失败进入FAILED/BLOCKED；可诊断件留受控 `failed/<run_id>` 并标DRAFT_PARTIAL，不进入可交付索引。状态机/恢复/并发实现当前NOT_IMPLEMENTED。

1. 授权输出根下创建独占、不可预测的新run暂存目录，同一文件系统；先规范输入/冻结来源/计算canonical，再写四临时文件。禁止写用户已有最终路径、跨卷rename假原子或跟随恶意链接。
2. 每文件写完关闭/刷新，重新解析/打开、全量结构/同源/安全校验；真实转换PDF并收集页/字体/视觉证据；两XLSX声明模式及缓存校验。失败保留已生成件以供诊断，但标四文件门禁FAIL或环境BLOCKED。
3. 将已校验manifest与canonical摘要、四文件字节摘要、review证据写入暂存集。READY仅指四件齐全且全部门禁通过/适用；未审视觉、无PDF、空缓存、未知授权或混run不得READY。
4. 以**整run目录的同卷原子rename或经过实测等价提交指针机制**一次发布；不是连续四次rename就称整集原子。Windows目录/锁/杀进程/断电前后语义必须专项实测，未经验证记BLOCKED。已有目标目录用独占失败，不覆盖。
5. 原子提交后重新读取正式路径精确manifest和四文件，并核对字节摘要、格式、数量与五标识；发布索引只指向完整集。写API成功不等于发布成功。读取端只认可完整已提交manifest，不扫描半成品为成功。
6. 并发run隔离，锁/过期锁有受控恢复；进程崩溃在每一阶段注入，下一次启动识别孤立暂存/已发布集，不错误合并、不清理用户文件。清理仅授权暂存，失败产物按权限保留期限。
7. 发布后任何编辑产生新版本/新run，旧目录不可变；转换失败/磁盘满/文件占用/权限不足/杀进程/校验错/文件冲突时旧发布仍完整可读。不能四份部分失败却对用户返回整体成功。

未来测试：`T-PUBLISH-ALL-OR-NOTHING`、`T-PUBLISH-CRASH-EACH-STATE`、`T-PUBLISH-CONCURRENT`、`T-PUBLISH-NO-OVERWRITE`、`T-PUBLISH-READBACK`、`T-PUBLISH-FAILURE-RETAIN`，均NOT_IMPLEMENTED。恢复策略与原子性必须实测，目录rename方案不是既有能力声明。

## 10. 视觉、数值与独立参考验收的证据格式

每条门禁记录 `test_id,requirement_id,pv_type,chapter_id/content_id,output_file,sheet/cell/page,model_version,run_id,input_hash,source_snapshot_id,result_hash,expected,actual,tolerance,status,evidence_path,reviewer,reviewed_at`；证据路径受控且脱敏。评审可记录缺陷严重性、修复版本/复验，禁止只有一句“人工看过”。

- 自动结构：真格式/可解析、18章100子项与13附录26子项、29核心sheet、符号术语/来源/元信息覆盖。
- 自动数值：能量/容量/损失/收入/投资/税折旧/本金/现金流平衡；月年图表与两套现金流全期；独立程序/手工参考值校验发电/NPV/IRR/静动态回收/LCOE/DSCR；IRR无根多根、未回本等明确原因。
- 属性/变形：在其他条件完全相同时，投资升高不使项目NPV升高，交付电量下降不使同结算收入增加；同负荷/上网约束能量守恒；输入变化使相关数值/报告/来源账和哈希重新生成。真实数值校验不能替换成字符串断言。
- 人工视觉：DOCX渲染页、PDF页面、两个XLSX全部sheet的代表区域/打印样张；检查中文/宽表/分页/图题/图例/单位/源注/公式/色彩对比、无裁切/遮挡/乱码；每个sheet至少标题/输入或结果/末尾与宽表处。大时序表重点检查不隐瞒截断。
- 打开/编辑/重算：约定的Word/PDF/Excel或兼容查看器名称版本、实际打开结果与保存副本；编辑后读回；重算模式要实测缓存与数值变化。解析库通过不能代替真实查看器/视觉。
