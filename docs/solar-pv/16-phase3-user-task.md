## 二、Phase 3 总体目标

本阶段需要建立独立、可复现的光伏项目计算体系。

计算链路：

项目规范化输入
→ 资源参数和工程方案
→ 装机容量及电气配置
→ 光伏发电量
→ 电力消纳
→ CAPEX
→ OPEX
→ 折旧和资产更新
→ 收入及税费
→ 融资与现金流
→ NPV / IRR / LCOE / 回收期
→ 敏感性分析
→ 风险识别
→ 统一计算结果 JSON

要求能够在私有本地环境中，通过 CLI 或 Python API 使用明确标记的合成样本完成真实计算。

本阶段可以先使用 `SYNTHETIC` 测试项目和明确的数值假设验证算法。

Phase 4 才实现正式资源、电价、政策及市场数据适配。

因此 Phase 3 不得声称已经完成真实站址的气象资源核验，也不得在合成计算结果上生成未经授权的真实项目投资结论。

## 三、89 条公式的完整实现与解释

### 3.1 公式注册表必须成为唯一依据

Phase 1 冻结了 89 条公式、281 个域字段映射，以及更多符号和索引定义。

请逐条审阅这些公式，并建立真实的执行映射。

每条公式至少需要记录：

- formula_id。
- 中文名称。
- 英文名称。
- 数学表达式。
- 所属业务模块。
- 输入字段。
- 输出指标。
- 变量及下标解释。
- 单位及量纲。
- 常数及其数值来源。
- 适用项目分类。
- 适用条件。
- 计算步骤。
- 边界条件。
- 舍入规则。
- 误差容限。
- 数据来源要求。
- 是否可以实际执行。
- 对应测试。
- 数值验证证据。

对于求和、求根、年序列、集合索引等不对应用户字段的符号，应保留独立符号定义，不能为了满足字段映射而伪造 field_id。

每条公式必须有明确的状态：

`IMPLEMENTED_TESTED`

`NOT_APPLICABLE`

`BLOCKED_MISSING_INPUT`

`BLOCKED_METHOD_REVIEW`

`NOT_IMPLEMENTED`

这些状态只能依据真实执行、实际适用范围及相关测试设置。

某公式不适用于当前场景，不等于它在产品层面已经实现。

Phase 3 验收时，应分别统计：

- 注册表总公式数。
- Phase 3 适用公式数。
- 已实现并验证公式数。
- 当前项目不适用公式数。
- 方法待核实公式数。
- 未实现公式数。
- 未通过测试公式数。

**不能用“89 条公式已登记”或“89 条公式输入映射已完成”代替计算实现通过。**

### 3.2 公式说明格式要求

例如，首年简化发电量公式：

`E₁ = P_DC × (H_POA / G_STC) × PR`

必须写明：

- `E₁`：项目首年发电量，单位 kWh；下标 `1` 表示第一个运行年。
- `P_DC`：组件直流侧标准测试条件下的标称装机容量，单位 kWp；`P` 表示功率，`DC` 表示 Direct Current，直流。
- `H_POA`：组件平面年总辐照量，单位 kWh/m²；`H` 表示累计辐照量，`POA` 表示 Plane of Array，即光伏组件阵列平面。
- `G_STC`：标准测试条件参考辐照度，单位 kW/m²；`G` 表示辐照度，`STC` 表示 Standard Test Conditions，即标准测试条件。
- `PR`：Performance Ratio，性能比，无量纲。
- `×`：乘法。
- `/`：除法。

说明必须包含公式的量纲一致性、计算边界、必要输入和不能使用的情况。

如果采用 PVWatts 或其他工具提供的已含损耗发电量，不允许再次重复乘以包含相同损耗的 PR。

以上只是格式示例，实际公式表达式、损失边界及定义必须与冻结注册表和选定计算方法一致。

所有公式均须达到相同解释深度。

### 3.3 需要覆盖的计算领域

至少包括：

- 工程可利用面积及容量估算。
- DC/AC 容量及容配比。
- 太阳能辐照量和发电量。
- 温度及系统损耗。
- 年度组件衰减。
- 系统可利用率。
- 限电和弃光。
- 光伏发电与用户负荷匹配。
- 自发自用电量和比例。
- 余电及售电量。
- 工程总投资。
- 年度运营费用。
- 设备更新支出。
- 折旧和残值。
- 电费节省与售电收入。
- 税费。
- 建设期与运营期现金流。
- 融资和偿债。
- 净现值。
- 内部收益率。
- 静态与动态回收期。
- 平准化度电成本。

- 敏感性分析。

任何已冻结但没有列在上述示例中的计算要求仍必须保留。

## 四、建立独立计算模块

推荐在现有 `services/solar-pv-engine/` 中扩展计算层。

可参考以下职责划分：

- `solar_resource`：辐照和资源参数计算。
- `capacity`：装机容量与方案参数。
- `energy_yield`：发电量与衰减。
- `losses`：系统损失与可利用率。
- `consumption`：自用和余电消纳。
- `capex`：建设投资。
- `opex`：运营费用。
- `depreciation`：折旧及资产更新。
- `revenue`：收入和节省电费。
- `tax`：税费及其计算假设。
- `financing`：融资及偿债。
- `cashflow`：年度现金流。
- `financial_metrics`：NPV、IRR、回收期、LCOE 等。
- `sensitivity`：敏感性分析。
- `scenarios`：多方案计算。
- `calculation_graph`：计算依赖和执行编排。
- `result_contract`：统一计算结果结构。

目录可根据现有代码结构调整，但职责不能混乱。

禁止出现两套互不兼容的计算引擎或字段定义。

### 4.1 计算精度

财务金额优先采用 Decimal 等明确精度策略。

工程计算可以根据算法需要使用浮点数值方法，但必须明确容差、数值稳定性及舍入规则。

不能简单对所有中间结果提前保留两位小数。

对于不同数值类型，分别规定：

- 输入精度。
- 中间计算精度。
- 输出精度。
- 舍入方式。
- 比较容差。
- 异常值处理。

零值、负值、极小值、极大值、无穷值和 NaN 必须根据业务语义拒绝或明确处理。

不能用一个通用的异常捕获把计算错误变成 0。

## 五、光伏发电量计算引擎

### 5.1 工程和资源输入

支持经过校验的：

- 装机容量。
- 组件功率及数量。
- 逆变器容量。
- DC/AC 比。
- 组件倾角和方位角。
- 组件平面辐照量。
- 气温和适用的组件温度参数。
- 遮挡损失。
- 积灰损失。
- 线损。
- 逆变器损失。
- 失配损失。
- 系统可利用率。
- 限发和弃光。
- 首年及后续年度衰减参数。

不能把 GHI 水平面辐照量直接当作 POA 组件平面辐照量。

如果执行所选模型需要温度、倾角或其他参数而数据缺失，必须按模型契约报告缺口。

不能随意填入所谓行业平均值。

### 5.2 发电量输出

至少提供：

- 月度发电量。
- 年度发电量。
- 单位装机发电量。
- 等效利用小时数。
- 系统性能比。
- 损失分项和综合损失。
- 首年发电量。
- 全生命周期年度发电量。
- 逐年衰减结果。
- 累计发电量。
- 限电前后电量。

对于明确具备相应输入数据的场景，支持更细时间粒度的计算。

对于不支持或缺少足够数据的情形，必须明确限制，不能通过平均分配月度数据伪造逐小时发电曲线。

### 5.3 避免重复损耗

必须建立系统损耗边界模型。

如果某项损耗已在上游发电量中计算，下游不得重复扣除。

重点检查：

- 温度损失。
- 逆变器效率。
- AC/DC 线路损失。
- 设备停机。
- 限电。
- 遮挡。
- 首年衰减。
- 年度性能衰减。

必须设置有针对性的重复计损测试。

## 六、工商业光伏电力消纳计算

这一模块应与集中式电站的售电模型隔离。

### 6.1 负荷匹配

对于具备逐小时或更细时间粒度负荷与发电序列的项目，按一致的时间区间进行匹配。

至少计算：

- 光伏总发电量。
- 站内自用电量。
- 余电上网电量。
- 弃光电量。
- 自发自用比例。
- 上网比例。
- 消纳约束造成的损失。
- 自用电量带来的电费节省。
- 余电销售收入。

计算必须处理时区、时间区间长度、缺失时段和数据对齐。

只有全年总用电量的情况下，不得声称能够准确计算小时级自用率。

如果采用典型负荷曲线，必须标明它是情景假设而非企业实际负荷。

### 6.2 电价模型

支持明确输入的：

- 单一电价。
- 分时电价。
- 合同折扣电价。
- 余电销售价格。
- 市场交易价格序列。
- 对应费用和交易成本。

不同电价模式必须有适用条件和生效时间。

本阶段不自动抓取全国或省级真实电价，不硬编码某个地区历史价格作为全国默认。

所有价格必须绑定计量边界、价格年份、币种、含税口径和来源。

## 七、工程投资和运营费用计算

### 7.1 CAPEX

CAPEX 即 Capital Expenditure，资本性支出或项目建设投资。

必须按冻结模型拆分设备、安装、土建、并网、土地/屋顶专项、其他费用和预备费。

支持数量乘单价、定额估算、明确的分项总价等受控方法。

输出：

- 各项投资。
- 汇总投资。
- 单位装机投资。
- 费用占比。
- 含税与未税口径。
- 已知费用与假设费用。
- 用户预算与实际估算的差异。
- 不确定费用项。

不得混合不同价格年份或不同含税口径。

### 7.2 OPEX

OPEX 即 Operating Expenditure，运营支出。

至少支持：

- 年度运维费用。
- 租金。
- 保险。
- 清洗。
- 管理费用。
- 交易费用。
- 设备维修。
- 定期更新支出。
- 通胀或费用增长假设。

输出全生命周期年度费用明细。

组件或逆变器更换等资本性支出与日常运维支出应按相应财务口径区分，不能重复计算。

### 7.3 折旧

实现适用的资产折旧方法，并明确：

- 资产原值。
- 折旧基数。
- 折旧年限。
- 残值率。
- 折旧起始时间。
- 年度折旧费用。
- 累计折旧。
- 期末账面价值。

必须区分折旧和现金支付。

折旧作为非现金费用影响利润和适用税负，不得被错误地从现金流中直接重复扣减。

如涉及不同税法或会计折旧口径，按明确输入和适用假设计算，不能宣称未经核验的税收政策必然适用于某个项目。

## 八、全生命周期财务计算引擎

这是 Phase 3 必须重点验收的模块。

### 8.1 计算周期

支持可配置项目评价期。

默认的 25 年可以作为明确披露的测算情景，但不能认定所有项目合同或设备寿命均为 25 年。

应分别处理：

- 建设期。
- 投产时点。
- 运营期。
- 设备更换年份。
- 融资期限。
- 合同期限。
- 期末残值和其他退出现金流。

不得把建设期和第一个运营年混淆。

### 8.2 年度现金流

至少计算：

- 年度发电量。
- 自用与销售电量。
- 节省电费。
- 电量销售收入。
- 运营费用。
- 折旧。
- 适用税费。
- 设备更新支出。
- 营运资金及其他适用现金流。
- 资本性投资支出。
- 贷款提取。
- 利息。
- 偿还本金。
- 项目层现金流。
- 股东资本金现金流。
- 年度累计现金流。

必须明确未融资的项目层口径与融资后的股东权益口径。

### 8.3 必须计算的财务指标

至少包含：

**NPV：Net Present Value，净现值。**

**IRR：Internal Rate of Return，内部收益率。**

**LCOE：Levelized Cost of Energy，平准化度电成本。**

**DSCR：Debt Service Coverage Ratio，偿债备付率。**

**Simple Payback Period：静态投资回收期。**

**Discounted Payback Period：动态投资回收期。**

还需要包括：

- 项目投资 IRR。
- 资本金 IRR。
- 税前与税后评价。
- 盈亏平衡电价。
- 年度和累计现金流。
- 全生命周期项目收益。

所有公式必须说明现金流时间点、折现率口径、税前税后口径及单位。

### 8.4 复杂财务边界

必须测试：

1. 投资额为零或非法。
2. 发电量为零。
3. 售电收入为零。
4. 负电价情景。
5. 长期亏损项目。
6. 项目始终无法回收投资。
7. 贷款利率为零。
8. 贷款期限大于或小于项目期限。
9. 没有贷款。
10. 建设期利息。
11. 非等额本金还款。
12. 设备中途更换。
13. 不同折现率。
14. 负 NPV。
15. 多次现金流符号变化。
16. IRR 无解或有多个候选解。
17. 税前、税后与融资口径切换。
18. 价格与成本随年份变化。

IRR 数值方法需要检查收敛、解的有效性及多解情况。

无 IRR 或存在多个经济含义不同的 IRR 时，必须明确返回相应状态，不能制造唯一有效收益率。

财务指标之间必须能够相互核对。

## 九、敏感性和多情景分析

必须支持：

- 基准情景。
- 乐观情景。
- 悲观情景。

并具备独立参数扰动能力。

至少覆盖：

- 建设总投资。
- 光伏发电量。
- 售电价格。
- 自发自用比例。
- 弃光比例。
- 运维费用。
- 融资利率。
- 折现率。

具体参数变化幅度应来自冻结规范或明确配置，不应硬编码成无法修改的参数。

每次情景变化必须执行真实重算，而不是直接对最终 IRR 或 NPV 乘一个系数。

输出基准值、变化值、变化幅度、重算结果及对应的输入参数版本。

如果情景条件互相矛盾，要拒绝计算并给出原因。

不得伪造概率分布或项目成功概率。

## 十、九类光伏场景与计算边界

2. 地面集中式光伏的独立计算链路。
3. 其他类别的计算能力边界和扩展接口。

如果两类项目由于缺少已核实的计算方法而无法完成某项专业计算，必须标记具体阻断，不得借用不适用的行业模型。

农光、渔光、储能等其他类型，按冻结路线在后续阶段逐项实现。

**不能用共用财务引擎的通过结果冒充九类光伏项目已经全部完成独立 E2E 验收。**

## 十二、测试与数值验证

不接受只检查代码没有报错的测试方式。

必须形成完整的专业数值验收。

### 12.1 公式专项测试

对于本阶段应实现的每条公式：

- 正常样例。
- 边界样例。
- 异常样例。
- 单位样例。
- 不适用样例。
- 缺失输入样例。
- 结果独立校核。

涉及集合、时间序列或条件分支的公式，还要覆盖相应分支。

不能只检查公式方法是否存在。

### 12.2 独立数值校核

至少建立两种不同的核验方式：

- 与经过确认的参考算例或独立手工/表格计算进行对照。
- 使用独立测试算法、性质测试或数值不变量进行复核。

不能使用同一段生产公式计算“预期值”，再反过来证明生产代码正确。

对于 NPV、IRR、LCOE、偿债及折旧，应设置可手工复算的小规模参考样例。

### 12.3 计算一致性

至少验证：

- 月度合计与年度电量一致。
- 年度电量与累积电量一致。
- 发电量、有效电量、弃电量的边界一致。
- 自用与上网分配不超过可分配电量。
- 投资分项与总投资一致。
- 年度费用与汇总值一致。
- 折旧累计额符合折旧基数及残值约束。
- 融资提款、利息、本金及余额一致。
- 年度现金流与累计现金流一致。
- 项目 IRR 和资本金 IRR 使用不同正确口径。
- 情景变化能够触发实际重算。
- 未验证或缺失的参数不能被偷偷替换。
- 计算结果与输入哈希、来源快照和公式版本一致。

### 12.4 场景测试

至少建立：

- 工商业屋顶完整合成项目。
- 集中式地面完整合成项目。
- 无贷款项目。
- 带融资项目。
- 项目长期亏损。
- 项目不能回本。
- 低自用率项目。
- 高弃光项目。
- 设备中途更换项目。
- 不同建设期项目。
- 缺失资源参数项目。
- 缺失税费依据项目。
- 多 IRR 或无有效 IRR 项目。
- 跨分类错误输入项目。
- 价格变更后的重算项目。

测试数据必须明确标记 SYNTHETIC，不得冒充真实项目。

### 12.5 回归与保护

继续执行：

- Phase 2 输入功能回归。
- 原有 WorkBuddy 产品回归。
- 基线检查器。
- 保护文件 SHA-256 检查。
- Git diff 检查。
- 凭据及隐私扫描。
- 新增源码编译与实际 CLI 测试。

原有 Windows 符号链接跳过项保持独立记录；条件允许时补充对应环境测试，但不能把其他测试成功代替这些测试。

不得因为新增测试耗时而删除旧用例。
