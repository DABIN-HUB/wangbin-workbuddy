# Q06 FIX-5 · 输入输出与错误契约（增量，不替换 V2）

依据 `requirements.md` BID-01–08/F02–F04、`input-output-contract.md` 原四维/错误/安全合同、`fix5-requirements.md` F5-01–04；生产入口仍为从候选包解压执行 `scripts/check_response.py --tender <UTF-8 txt/md> --mode check --response <UTF-8 txt/md> --output-dir <dir> --project <安全单段名> [--evidence-file <UTF-8 txt/md>]`。准备模式/补遗/目录及旧 `analyze_tender.py --input` 必须按原合同保留。**必需**核查输入为招标和回应；实际证据文件零或多份只可显式传入；目录 CSV/XLSX 可选，不能以清单代替文件。正常输入限普通非 symlink、≤1MiB、UTF-8；材料名和文本不能触发自动目录扫描。项目名须安全，存在输出拒绝覆盖；不回显原始私有绝对路径/全文。

可观察记录（内部结构不强制特定字段名，输出必须可回溯）：`requirement_id` + 招标对象/条件/时点/来源、匹配回应行及候选、按对象和时态隔离的事实状态/肯否/证据行、每个文件的“实际提供”与“正文证明力”、冲突两侧来源、四维状态/判据/确定缺口/待确认原因。先确定义务—回应绑定，再判事实；明确当前不足、未知、将来附条件、当前肯定、同对象矛盾五类不可经泛词交集相互转化；同一文件标题与正文的证明力不可由文件名决定。证据引用真实 basename:1 起始行，清单引用表/行，脱敏限长。

四维顺序：响应存在 / 条件覆盖 / 附件实际提供 / 内容支持。H06 `已定位 / 待确认 / 不适用 / 不适用`：未知原因指 `response.md:1`，待确认表/MD 需人工确认，不能在已覆盖范围；这不是确定未部署。H10、H12 `已定位 / 可能不充分 / 已提供（可读文本） / 不支持（文本层面）`：**文件存在**与**此文件明确缺正文**同时成立，矩阵缺口标具体缺正文及 `营业执照.txt:2`（H10，标题 L1 可并列）或 `营业执照.txt:1`（H12）；附件核对保留文件实际提供及负证位置；MD 确定需补/未覆盖，不用泛化待确认替代。只否定该文本的证明力，不推断企业未持有执照。若同文件出现来源可定位的正反材料，必须两者并存并标冲突待确认，不能丢弃负句或强行宣告无证。

成功输出恰两文件：`{项目名称}-投标响应检查.xlsx` 五表按 `核查概览`、`要求响应矩阵`、`附件核对`、`补遗与版本`、`待确认事项` 顺序，及 `{项目名称}-提交前核对清单.md`。概览逐维逐状态计数由矩阵推导；未知是状态且单独计数，不能填零或混入已覆盖。矩阵保留原句限长摘录、要求 ID、响应/证据位置、四维和缺口；附件核对绑定同一义务的实际文件及正文支持；无正式补遗须明示无可证关系；MD 确定缺口/人工确认/覆盖/未覆盖不得使同一行又确定缺口又称全覆盖。保留安全纯文本单元格与旧 JSON 快照。

失败：沿用原错误合同 `MISSING_TENDER`/`MISSING_RESPONSE`、`INPUT_NOT_FOUND`/`INPUT_NOT_REGULAR`/`INPUT_SYMLINK`、`INPUT_TYPE_UNSUPPORTED`/`INPUT_TOO_LARGE`/`INVALID_UTF8`/`INPUT_READ_FAILED`、`CATALOG_SCHEMA_INVALID`/`CATALOG_READ_FAILED`、`RELATION_INVALID`、`OUTPUT_PATH_INVALID`/`OUTPUT_EXISTS`/`OUTPUT_WRITE_FAILED`；错误用例非零，不留看似完成的双文件。明确不明的材料关联只可按合同留候选待确认，不将未给材料当作不存在于现实。FIX-5 不新增文件格式、不认证真实证照/资质/法律效力、不改变旧错误语义。开发/独立 QA 的新版回放和错误探针此时 `NOT_TESTED`。
