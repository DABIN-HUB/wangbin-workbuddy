# Q06 FIX-6 · 输入—统一判定—输出合同（补充 V2/FIX-5）

基于 `fix6-requirements.md` F6-01–05；原 `input-output-contract.md` 及 `fix5-input-output-contract.md` 仍有效，不改文件格式或原 94 项预期。核查模式 CLI 保持 `scripts/check_response.py --tender <招标.txt/.md> --mode check --response <回应.txt/.md> --output-dir <dir> --project <安全单段名称> [--evidence-file <材料.txt/.md> ...] [--attachment-catalog <CSV/XLSX>] [--amendment <正式补遗>]`；`--tender`/`--response` 在 check 必需。证据文件、目录、补遗仅显式传入；不能把目录或回应中的“见附件”当实际文件。准备模式仍只按原合同需招标文件；旧 `scripts/analyze_tender.py --input <单文件>` 的 JSON 行为和快照不变。输入为普通非 symlink、≤1MiB、UTF-8 的受支持文件；CSV/XLSX 目录由既有解析契约读取，禁自动枚举邻接目录。

每个要求行至少携带 `唯一ID`、原编号、要求原文/来源 `tender.txt:1`、明确条件、对象/时间；对每个绑定的相关回应，保存其原句、源 `response.md:行`、对象及当前/未来/未知/条件事实。内部字段不强制命名，但输出可审计全部候选、正反两侧位置与判据：在同对象同时间事实集合聚合，肯定+否定→冲突；纯未知→待确认；确定当前不足（即便附未来计划）→可能不充分；只有明确当前肯定且没有反证→已覆盖；仅未来/条件缺现况不能推断已覆盖或确定当前不可用，保留条件并待确认（如有明确未满足当前无条件义务，则依据原句列不足）。不同对象的事实不能合并。`response.md:2` 不因其编号与单项招标编号不等便从 F04 丢失，也不能因编号相等而借 F05 另一对象的肯定。功能判断禁止以 token 交集作为最终覆盖依据。

四维原枚举与顺序不变：①响应存在状态（已定位/候选待确认/未找到等）；②条件覆盖状态（已覆盖（文本层面）/可能不充分/待确认等）；③附件实际提供状态（不适用/已提供（可读文本）/仅目录登记/未提供（限已提供材料）等）；④内容支持状态（不适用/支持（文本层面）/不支持（文本层面）/待确认/未核验）。F01 `(已定位,待确认,不适用,不适用)`；F02 `(已定位,可能不充分,不适用,不适用)`；F04 两句 `(已定位,待确认,不适用,不适用)`；F05 第一行 `(已定位,已覆盖（文本层面）,不适用,不适用)`、第二行 `(已定位,可能不充分,不适用,不适用)`；F08 `(已定位,可能不充分,已提供（可读文本）,不支持（文本层面）)`。这些均指原 QA expected，不是新实现 actual。F08 材料 `营业执照.txt:2` 是明确无正文反证，即使 L1 有封面标题；“证照正文未附”/“仅有封面，正文未附”等可判等价否定，但单独标题、部分登记摘要不得凭猜测定负；同文件 L1 正文与 L2 无正文互斥则待确认并给双行。文件已提交≠文件内容支持，缺件不等于现实中不存在。

成功恰两产物：`{项目}-投标响应检查.xlsx`（工作表严格依序 `核查概览`、`要求响应矩阵`、`附件核对`、`补遗与版本`、`待确认事项`）和 `{项目}-提交前核对清单.md`。矩阵一义务一行，四维/缺口/建议及真实要求、回应和证据 `basename:1-based-line`；多回应位置都列出，且正反摘录或理由可见，不能只列双位置但只呈现首条肯定。附件核对逐义务绑定实际文件/提供状态/正文支持/反证位置；补遗无已证明正式替换关系时保持原明确行；待确认事项写明未知或冲突两端及人审动作。概览每维每状态计数 = 矩阵对应状态逐行计数，合计各为矩阵义务数，不把未知/null 当零。MD 的“确定需要补资料（已提供范围）”“需要人工确认”“已覆盖范围（仅文本层面）”“未覆盖范围（仅已提供材料）”与矩阵相符：F01/F04 仅人工确认，不称已覆盖；F02/F05 第二行/F08 确定缺口及未覆盖，不用笼统人工确认遮蔽；F05 第一行可列覆盖；F08 附件行保留已提供及负证 `营业执照.txt:2`。全部限定文本层面、标注源文件，禁止公式/宏注入，脱敏及路径边界继承旧约。

错误仍沿用旧契约：`MISSING_TENDER`、`MISSING_RESPONSE`、`INPUT_NOT_FOUND`、`INPUT_NOT_REGULAR`、`INPUT_SYMLINK`、`INPUT_TYPE_UNSUPPORTED`、`INPUT_TOO_LARGE`、`INVALID_UTF8`、`INPUT_READ_FAILED`、`CATALOG_SCHEMA_INVALID`、`CATALOG_READ_FAILED`、`RELATION_INVALID`、`OUTPUT_PATH_INVALID`、`OUTPUT_EXISTS`、`OUTPUT_WRITE_FAILED`；报 `ERROR <CODE> role=<...>`，非零且不得留下貌似完成的两文件。原独立探针缺回应、坏 UTF-8、不支持 PDF、坏目录、路径逃逸应 exit 2 且无产物，正控 exit 0；其他未复测项 `NOT_TESTED`。不得将读失败等同空文件/零件，不认证现实证照与法律效力。
