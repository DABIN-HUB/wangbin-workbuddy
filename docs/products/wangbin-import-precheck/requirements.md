# 数据导入前检查｜MVP 需求冻结

product_id: `wangbin-import-precheck`；task_id: `t_b27907cb`；拟用版本 `0.1.0`（尚未注册/发布）；权威依据：`wb-non-solar-v2-authoritative-spec.txt` §01、§06–14、§24–45，尤其 §14.1–14.9。本文是独立预期，不是实现运行结果。

## 用户、价值和流程
客户/供应商资料导入操作员上传原始 CSV/XLSX，附目标模板或文字字段说明、可选参考表，以自然语言要求预检。系统只读识别区域与来源→提出字段对应→确认影响结论的歧义→运行已知规则→产出可定位问题与未检查项→仅凭明确授权形成转换/候选或合格部分与隔离记录→补资料或改规则时重跑并比较版本。用户不需手写 JSON、逐列映射或预先整理模板；已明确说明的规则不重复索取确认。独立价值在于导入前的字段映射、可复现的逐行规则判定、参考表快照、候选变更审计和每行去向，而非重新命名既有采购对账/三单匹配或改提示词。基线工厂本地 catalog 未登记本 ID；相似性 CLI 在未注册时退出 2，**并非相似性 PASS**；注册前由后续角色复核。§05、§14、T00 handoff。

## 功能与门槛
- IMP-01 [§14.5] 定位文件、工作表、表头、数据区、原始记录稳定 ID、输入数与完全空白行数；多候选工作表/表头需确认，不默认第一张。
- IMP-02 [§14.5] 从源字段与目标模板/文字说明提出映射；唯一且精确的对应可用；争用、重复、语义一对多时确认；未确认不作改变语义的转换。
- IMP-03 [§14.5] 按已确认规则逐字段逐行检查，独立发现并列，不因首错停止；按文件、行、列/单元格与原值追踪。
- IMP-04 [§14.5] 单/组合唯一键保留大小写、空格、前导零；仅已授权标准化改变比较键；缺组合键字段报缺失而不聚成重复组。
- IMP-05 [§14.5] 参考表按本次快照成员核查；缺参考表为未检查；参考键重复为参考资料歧义，不能随机选择。
- IMP-06 [§09、§14.5] 区分文本编码和数值显示格式；`00123`≠`123`，已失精度的长数值不虚构恢复。
- IMP-07 [§14.5] 建议不等于修改；每次已授权真实修改保存原/新值、规则、授权；原件只读。
- IMP-08 [§14.5] 映射和必要转换已确定才生成候选；有阻断记录不得删除后声称全可导。只有明确要求合格部分时才分流，所有输入记录恰好有去向。
- IMP-09 [§12、§14.5] 补参考表、变更规则、纠错后按当前条件重算受影响判断；旧结果留存，run 区分，重复提交同文件不重复发现。

## 状态、范围和非目标
默认只检查；有完整目标字段说明方可称“目标模板预检”；没有则只做有依据的有限数据质量检查，并列明未检查目标规则。缺文件/不可可靠解析为 NEEDS_INPUT 或 REJECTED；可处理部分产出而有范围缺口为 PARTIAL；已执行全部可检查规则且文件生成成功为 COMPLETED，**不代表数据无问题或可导入**；内部失败为 FAILED，不生成虚构成功链接。缺条件的规则标记未检查，未知 required/长度不是 false/255。数值 0 不是空，文本 `NULL`/`N/A` 不自动为空。

不写 ERP/CRM、不保证未知系统导入成功、不删除合并业务标识、不自动修复或上传外部服务；不接入付费 API/跨客户数据库、不执行输入公式/宏/文档内指令。不把模板建议或模型猜测升格为系统事实；不自动导出“已全部修好”。首版支持原始 CSV/XLSX 入口及 §14 的报告；其他格式只按明确支持边界拒绝。禁止修改采购既有规则/资产/许可证、主仓和光伏工作树。版本待开发者注册时确认；任何平台安装、评测、审核、发布和许可证结论均未验证。

## 冲突核对与决策
§14.7 的 4 发现 = 重复组影响行2与3各一发现 + 行3参考值一发现 + 行5缺名一发现；3 条受影响记录 = 行2、3、5（不是 4 条）。无阻断记录数在核心示例为行4一条，前提是三类发现均标阻断（本合同定义这些已确认规则违规为阻断候选；缺条件的未检查不是判为通过）。§14.5 允许授权候选但 §14.7 禁止未授权“全修好”：两者按授权状态区分。缺参考表时不把未知成员算违规；有限模式绝不冒充目标模板完整通过。表格显示格式不是文本身份；原哈希不变是前后同一输入的断言。没有影响核心业务逻辑的待决冲突；具体资源上限与运行宿主支持待开发实测并记录，不可减弱冻结范围。

## AUDIT-R1 修复增补冻结（IMP-F01–F04；原 V2 合同保留）

本节为本轮新授权 §06、§12–18 的**增补**，不是重写原 T01 需求或重置历史计数。基线为精确 0.1.4 ZIP SHA-256 `536763a9c5d64d5b5b53364f5e6e7be93c13457351624b544a0b722b07955d3c`；独立证据见 `audit-r1-014-baseline.md` 与 `audit-r1-baseline-results.json`。旧 QA 在旧测试集中的 PASS 保留；本轮反例在旧包 L3 FAIL（F04 包内容 L1 FAIL），新包全部 NOT_TESTED。历史两轮返工不挪入新计数；本轮首次集中修复后由独立 QA 决定最多两轮自动退回修复，逐函数修改不算轮次。用户仍是导入操作员，独立价值仍是**目标映射 + 行级确定性检查 + 有证据的分流**，不是模板改名或提示词修饰；不写系统、不自动修原件、不补造未声明规则。

- **F01 目标业务数据**〔V2 §14.3/14.5 IMP-02/06/08，审查 §06〕：目标字段对应确认后，候选的业务列必须按目标字段命名；有目标模板以模板原有字段顺序为准，仅有已确认规则时按规则明确的目标字段顺序且在报告中登记顺序及依据。源表列序不能覆盖模板序；未映射源列不得夹带。`row_id`、`source_line` 默认仅在报告/独立追踪信息或隔离记录出现；**仅当目标模板明确包含并要求它们**才作为业务列出现。文本 `00123` 和长文本编码以文本无损导出，XLSX 原存数值已丢失精度时只能标风险，不臆造原文。两个源列争一目标/多目标歧义不得输出声称可用的目标候选，先要求确认；不妨碍独立可查项目的有限检查。
- **F02 最终值规则**〔V2 §14.5 IMP-03/04/05/07/09，审查 §06〕：分别追踪原值检查及最终**实际导出**值检查；每行每目标字段的已确认且适用的必填、类型、最大/最小长度、允许值、明确日期格式、参考快照成员，及全表最终单/组合唯一键必须在映射及全部授权转换后重新判定（未声明的保持 UNKNOWN）。最终阻断和分流仅取最终值证据；原值旧错误如被修复须标已解决/历史而非继续阻断，新增问题则如实增加；同一最终规则+行不双计。原/最终值、规则来源、授权、检查覆盖、问题前后变化和原行坐标均可追踪；空值不等于数值 0，缺组合键不构成重复组。单纯只有唯一键重算不构成 F02 完成。
- **F03 资格三态**〔V2 §14.5 IMP-05/08、A05/A06/A11，审查 §06〕：对本次已声明且影响目标资格的规则/映射，逐行区分 `已完成适用检查且无阻断`、`已证实违规`、`必要依据缺失/歧义而未验证`。缺已声明的参考表或重复参考键、必要映射/比较条件缺失时，不把该行误称规则已通过或直接导入合格；`--split` 的合格部分只能包含第一态。失败和待确认可同置隔离表但分别标出具体规则、原因及对应行，未知不能伪称不在参考表；未声明的最大长度等不臆造并不因此阻断全部记录。若用户**另外明确要求全量转换副本**，可保留全部原始业务行，但必须在报告/随副本可见的范围声明中逐行标明待复核及“非可直接导入合格部分”，且不得把它当 `--split` 合格部分。源业务行必须恰好有一个最终去向。
- **F04 统一交付**〔审查 §06/15/16〕：不覆盖 0.1.4 原 ZIP；新未占用版本的 README、SKILL YAML version、实际 ZIP 文件名、适用 manifest/catalog **candidate** 记录、包外交付清单一致。不要为了统一而提前把 candidate 激活为 active。元数据 name/中英文展示名及简介、真实作者、各三条双语 examples、解压后可用入口和随包规则须核实；明确 Python/第三方依赖版本区间及隔离环境准备，依赖许可依实际版本发行元数据与许可文本核对，未核实不自行改许可或发布。安全仍按 V2：原件只读、仅授权输入输出、路径及解压限制、禁宏/外链/文档指令、公式注入防护；不同环境的静态风险和实测结果分别记录。
