# 业务规则冻结｜IMP

权威来源：V2 §06–14（特别 §14.3–14.8）、§24、§31–32。规则为可检验合同，不是实现函数名。优先级：用户明确指定的本次有效规则/映射及模板已确认说明；矛盾时列冲突并暂停该判断，不按上传时间/文件自称最终版裁决；用户明确授权的标准化只改变约定范围。原始输入不因规则改变而重写。

|规则|可测试判定/缺条件处理|来源|
|---|---|---|
|IMP-R01 输入/定位|识别真实格式、编码/分隔符或 sheet、表头和区域；每条非空业务行得稳定 row_id＋原始坐标；完全空白行单列计数，不当业务记录；多候选不默选。|§09、§14.5 IMP-01|
|IMP-R02 字段映射|源与目标唯一精确且不冲突时可直接采用并记依据；两个源争同一目标、重复目标、语义一对多→待确认；不对未确认字段做改变语义的转换。|§06、§14.5 IMP-02|
|IMP-R03 已知逐行规则|确认的 required、data_type、min/max 长度、allowed_values、date_format 分别检验；空与 0 不等；`NULL`/`N/A` 文本不自动当空；规则缺失 UNKNOWN，不生成其违规或通过结论；同一记录多个独立违规分别输出。日期 `03/04/2026` 未定格式不可猜月/日。|§09、§14.3–14.5 IMP-03|
|IMP-R04 唯一键|对所有键字段均存在且可比的行，以原文本字面值精确比较单/组合键；默认不 trim、不大小写折叠、不去前导零；每个重复组计一次，每个受影响行出一条 DUPLICATE_KEY；组合键缺字段报告缺键及无法检查唯一性；只有该字段已声明必填时才另报必填违规，不能将缺键组成重复组。标准化仅显式授权并标记比较依据。|§09、§14.5 IMP-04|
|IMP-R05 参考快照|参考表已提供且键可唯一解析时检查成员；不在快照内标 NOT_IN_REFERENCE，不等于真实系统必然无效；缺表→未检查；参考键重复→REFERENCE_AMBIGUITY/待确认，不随机选；对应行不因此判值有效/无效。|§14.3、§14.5 IMP-05|
|IMP-R06 身份/精度|文本 `00123` 与文本 `123` 不相等；数值 123 配显示 `00123` 保留数值类型/显示信息，不能冒充文本 `00123`；长数字失精度需标风险/无法恢复，不反推原编号。|§09、§14.5 IMP-06|
|IMP-R07 修改审计|默认仅报告，建议与实际变更分开；仅用户授权的映射/转换对已声明范围执行，每个实际改变记录 row_id、字段、原值、新值、转换规则及授权依据；原件前后哈希相同。|§09、§14.3、§14.5 IMP-07|
|IMP-R08 候选与分流|映射及必要转换确定时才允许候选；阻断记录仍在不能标“可直接全部导入”，不得未经授权删除/合并/换标识。用户明确请求先输出合格部分才分出候选/隔离：按已确认阻断规则决定，所有原始行只落一边并可追溯；未检查项持续可见。|§14.5 IMP-08|
|IMP-R09 多轮重算|补表或改规则使用新快照重新执行受影响规则；保留旧 run 的结论与文件，新 run 展示新增/解决/持续；相同文件＋相同规则重复执行业务结果一致，不重复记录。文件不可访问则要求再提供。|§12、§14.5 IMP-09|
|IMP-R10 统计/状态|输入数是非空业务行数；有问题记录数为不同 row_id 并集；问题数为 finding 行数；重复组数为等价键组数；未检查规则数独立；执行状态与业务结论分离，未覆盖范围不得说全通过。|§10、§14.6–14.7|
|IMP-R11 安全|不执行 XLSX 公式、宏、数据中的指令、危险外链；导出以数据文本编码，防 `=`, `+`, `-`, `@` 等前缀触发公式（包含 CSV 重开）；路径/符号链接越界拒绝；不上传或读取未授权范围。|§09、§32|

核心示例：四行 input=[原行2 `(00123,甲客户,R01)`, 原行3 `(00123,乙客户,R99)`, 原行4 `(123,丙客户,R02)`, 原行5 `(00007,空,R01)`]，规则 customer_code 文本且必填、文件内唯一，customer_name 必填，region 属 R01/R02。R04 对行2/3各出重复问题（组数1）；R05 对行3出 NOT_IN_REFERENCE；R03 对行5出 MISSING_REQUIRED；总问题4、受影响行2/3/5共3、行4无阻断。原文 §14.7 明确本核心数值；禁止把重复组数误当重复问题数。行3“R99”是**相对本次参考快照**不在集合，不断言真实系统主数据不存在。无授权不得出“已修复全部”的文件。

冲突检查：`required=UNKNOWN` 与 `false` 不等价；无模板限定“目标系统合规”结论；参考缺失只能未检查，不能当无效；完成执行与成功导入不是同义；含原始问题的完整候选与明确授权的合格子集按授权门槛区分；日期歧义不能凭样例默认日期格式。上述规则之间未发现须重开用户决策的冲突。实现资源限制需在不减少本冻结能力的前提下另行实测并明确。
