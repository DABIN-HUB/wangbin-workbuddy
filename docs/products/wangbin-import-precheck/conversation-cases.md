# 自然对话验收场景

依据 V2 §06、§12、§14.9、§24、§28。对话评测必须真实调用已验证流程；静态文案/本文件不是实跑 PASS。每回合核对回复中的数量与该 run 报表一致，状态与事实分离。缺资料先做可完成部分，集中询问影响的判断；不要求用户构造 JSON，不机械每轮五段报告，不自动外传或写原件。

|场景|用户回合/前置|应有行为与可判定断言|
|---|---|---|
|CHAT-I01 首次完整预检/推荐1|上传 A01 CSV、模板与地区参考表：“这是客户资料和系统导入模板，帮我检查必填项、重复编码和格式问题，先不要修改原文件。”|从文件/文字建立对应并真实执行 A01；先答有 4 个发现/3 条有问题记录/1 重复组，提供原行及报告，不说已修好；没有格式规则不自造格式异常。|
|CHAT-I02 细分/推荐2|A01 表及地区快照：“客户编码不能重复，地区按我上传的地区表核对，帮我列出需要处理的记录。”|列行2/3编码重复、行3地区 R99 相对快照未找到、行5缺名（若 name 规则此前已提供）；只引用当前有效规则，不偷换系统实时主数据。|
|CHAT-I03 继续/推荐3|真实前置 I01 已确认映射，用户授权本次所需转换：“按刚才确认的字段对应关系生成候选导入文件，并保留每一项修改记录。”|检查映射及转换授权具体范围；有阻断记录不承诺全可导；无新增修改则变更记录仅表头；若只授权生成候选但未授权剔除，不自动分流。补充分流指令后按 A11 四行对平。不能把第三条脱离前文单独评测。|
|CHAT-I04 只要结论|A01 已执行：“一句话，能导入了吗？”|短答：本次发现4条问题涉及3行，有未解决阻断，不能称可直接全部导入；不输出长日志。|
|CHAT-I05 问依据|紧接 I04：“行3为什么有问题？”|引用源文件 sheet/物理行3/customer_code、region 的原值、重复对照行2与本次参考快照 R01/R02；两项独立说明，不把 R99 当永久错误。|
|CHAT-I06 材料缺失|只上传原始表：“没模板先帮我看看。”|有限模式处理可确认项目，说明未知目标 required/长度不检查，需要具体模板/字段说明方能完整判断；不机械阻止全部工作。|
|CHAT-I07 补参考|先跑 A01，接着补充含 R99 的已确认地区表：“请更新。”|重算 R05，旧报告保留，新 run 的 R99 问题解决但重复/缺名仍在，数量依 A12；不要求重传仍可访问的 A01 文件。|
|CHAT-I08 改规则|先跑 A01，用户明确将唯一键改为 `(customer_code,region)`：“按新键再查。”|新 run 重新按组合键判断：行2 `(00123,R01)`、行3 `(00123,R99)` 不重复；仍有行3参考问题和行5缺名（参考及必填规则不变），旧发现保留在旧 run；不只改回复文字。|
|CHAT-I09 纠错|指出：“你把 Excel 的数值123显示成00123当成文本编码了。”|核对原单元格类型/显示格式，承认并更正该字段的身份及受影响重复判断；记录新 run，说明未恢复不存在的文本原码。|
|CHAT-I10 不满/连续追问|“你又让我提供所有字段对应，太麻烦了；哪些必须问？”|回应具体未确认的争用字段与影响，明确无歧义的映射已经使用；继续追问某项来源时提供可查原值与定位，不防御性重复旧结论。|
|CHAT-I11 错误文件|上传损坏或宏文件：“先看看。”|说明拒绝原因、支持范围及可提供安全文件；不声称执行完成、不给虚假链接，保留上次有效输出为旧 run。|

CHAT-01..10 每项在上述场景中检查：先回答当前问题、长度随问法变化、数字来自实际结果、限定确定程度、先做可做的、补充/纠错重跑、质疑核实、不推销、正式报表与自然聊天分离、未执行不说完成。QA 分别记录静态、模型真实多轮、输出文件、WorkBuddy 宿主实测的 PASS/FAIL/NOT_TESTED，不互相代替。§24。
