# 输入输出与确定性合并契约｜wangbin-meeting-action-tracker V2

权威：附件19 §17.3–17.6（行1165–1273），规则 MTG-01..09 见 `requirements.md`。以下是为实现/自动验收冻结的接口细化，不增设未获授权的业务事实。

## 输入

| 参数 | 必需 | 允许值及字段 | 校验/空值 |
|---|---|---|---|
| `meeting_file` | 是 | 单个本次会议 TXT/MD/DOCX；可读正文、会议日期（如存在）、决议/任务语句与原文位置 | 格式白名单、实际可解析且有非空正文；无会议日期不拒绝绝对日期任务，但相对日期待确认。TXT/MD 用 UTF-8（允许 BOM），DOCX 仅正文/表格可读文本，不执行宏、外链。 |
| `previous_tasks` | 否 | CSV/XLSX 上次任务表；至少 task_id、任务内容、执行状态；存在的负责人、期限、确认状态、来源、历史事件不得丢 | 缺旧表=首版；有旧表缺上述核心字段/重复 ID/无法解析时拒绝合并并保留旧表原件。仅接受本产品导出四表或可明确映射的表头；其他表头报错，不静默猜列。 |
| `supplemental_evidence` | 否 | 补充完成记录的 TXT/MD/DOCX 或明确提供的文本；须含可定位 task_id 或唯一匹配的任务描述、证据内容与可追溯出处 | 不可定位时仅列待确认，不更新其他任务；“已完成”口头陈述≠验收证据。证据如编号/链接仅引用原文，不打开或宣称已核验链接。 |
| `corrections` | 否 | 用户明确更正：指向 task_id 或唯一可核实对象、字段、新值及用户原文；可带确认时间 | 不能定位/目标歧义时待确认。更正不覆盖源文件；在历史追加事件。 |
| `project_name` | 否 | 非空安全文件名文本，用户给定；未给时用中性“会议”并明确提示仅为导出名，不能当作真实项目归属 | 路径分隔符/控制字符/保留设备名拒绝或安全替换且告知；不允许路径穿越。 |
| `check_date`, `timezone` | 否 | 核查日 YYYY-MM-DD；时区为显式 IANA 名或明确 UTC 偏移；涉及跨时区时间比较必须提供时区 | 无核查日绝不判逾期；日期不合法/跨时区缺时区仅逾期“无法判断”，不冒用机器今天。 |
| `response_mode`, `draft_followup` | 否 | `summary`/`one_sentence`/`export`；跟进草稿仅显式 true | `one_sentence` 限一句简洁结论；`export` 写文件；草稿默认 false，不发送。 |

## 内部规范记录（输出列不必暴露全部实现字段）

Task：`task_id`（非空唯一稳定字符串）、`任务内容`、`来源`（文件/文本标识+段落或行位置+引文）、`负责人`（可空）、`负责人确认状态`（已确认/建议/待确认/未提供）、`截止时间`（ISO 日期或空）、`截止时间确认状态`（已确认/待确认/未提供）、`执行状态`（待执行/进行中/报告完成/证据确认完成/取消/提议待决/待确认）、`完成证据`（可空；有证据须源位置）、`逾期判断`（是/否/无法判断）、`逾期判断依据`（截止日、核查日、时区/不判理由）、`关联原任务`（可空）、`本次变化`。空值必须表现为空或“未提供”，不写 0；“未提及”不是状态迁移。

Event：`event_id`、`task_id`、`事件类型`（新增/内容变更/负责人变更/期限变更/进展/报告完成/证据确认完成/取消/重新开启/用户更正/冲突）、`原值`、`新值`、`来源`（文件标识、定位、引文）、`会议或用户确认时间`（缺时留空）、`是否存在冲突`。事件可包含提议但不得作为已确认值覆盖原字段。

### 稳定身份、匹配与冲突（MTG-01/02/05/08/09）

1. 同一次导入的来源指纹用文件原始字节 SHA-256 + 文件类型；不同路径但同字节属于同一导入。先按 `task_id`、事件类型、规范化原/新值及可区分的任务上下文构造语义身份，重复导入或仅改变行序但语义相同的记录不新增事件；事件来源另外保留文件指纹、原文位置与引文。不同来源重复报告同一值可以追加来源引用但不能捏造新状态迁移；矛盾的新值另立冲突事件。event_id 从语义身份派生并在历史中唯一、稳定，不采用导入时间、行顺序或工作簿行号。
2. 旧 task_id 是主键且优先保留。无显式 ID：先按项目上下文与具体任务内容/限定对象严格匹配，唯一可信候选才关联；仅相似名称或多候选不自动合并。首版新项的 ID 采用内容+项目上下文+首次来源锚点的稳定摘要（例如 `MTG-` 加摘要前若干字符，碰撞时增加长度至唯一）；不依赖列表位置，重导入和重排必须保持 ID。重排导致的原文定位变化可通过保留任务内容/上下文身份和已有来源历史关联，不能因此产生新任务。极相似但对象不同的事项保持不同 ID。人工明确指定旧 ID 优先于启发式匹配，若来源 ID 对应旧内容发生不相容变更则记录冲突而非偷换 ID。
3. 对同一任务字段的相容新增信息追加来源事件；明确用户更正指定唯一目标且可直接落地并记录前值。对于同等权威且矛盾的输入，保留上一确认值，新增冲突事件（含两个候选源及值）与待确认行，不能按上传顺序选胜者。取消与重新开启只有明确决议/用户指令方可迁移，建议/描述性引用不得迁移。补充事件只作用于关联项，未关联则待确认。
4. “报告完成”只基于可定位的完成陈述；“证据确认完成”要求与该任务明确关联的可描述验收/交付证据，引用证据原文；无法核验真实性时标明“提交材料所称证据，未独立核验”，不得将模型判断当外部验收。旧项未提及仅本轮变化“无新增进展”，不生成假进展事件；重复导入输出内容与事件集合不变。

### 日期与逾期（MTG-06/07）

会议日期必须来自本次材料或用户明确确认。只有单义相对语义且基准明确才换算（会议日 2026-11-06 的“明天”=2026-11-07）；“尽快”“下阶段”“下周”无单义日不得编造日期。有歧义的多个会议日期先问或列待确认。逾期仅在确认截止日和显式核查日（涉时区时有时区）齐全且任务仍需执行时计算：截止日 < 核查日为“是”，截止日 >= 核查日为“否”；取消/证据完成不进入逾期未完成名单；报告完成但缺证据标识需核实、是否继续判逾期须标“无法判断（完成未核实）”而不能悄悄当证据完成。日期无效、缺基准时“无法判断”并写明原因。

## 输出与失败原子性

`response_mode=export`：`{项目名称}-任务跟踪.xlsx`，恰好四个业务工作表且按以下顺序：

1. `当前任务`：`task_id,任务内容,负责人,负责人确认状态,截止时间,截止时间确认状态,执行状态,完成证据,是否逾期,逾期判断依据,来源,最近变更`。来源含定位，缺数据留空/待确认。旧项未提及保留且最近变更“无新增进展”。
2. `本次新增与变化`：`task_id,关联原任务,变化类型,原值,新值,确认状态,来源,event_id`；仅实际发生变化/提议的本轮行。
3. `待确认事项`：`task_id,待确认字段,候选值或问题,原因,候选来源,建议用户确认内容`；冲突每组有可见行；没有问题时仅表头。
4. `状态历史`：`event_id,task_id,事件类型,原值,新值,来源,会议或用户确认时间,是否存在冲突`；包含旧历史且稳定去重。

同时输出简洁自然语言会议决议摘要（可复制文本，导出模式保存为 `{项目名称}-会议决议摘要.md`）；只叙述有证据的新增/变化/未确认，不能把建议当决议或将“报告完成”写为验收完成。`draft_followup=true` 时额外在回复里给可复制跟进文字，标注草稿，不自动发送。`one_sentence` 只返回一句结论，不强制生成文件；后续若用户要求导出则按四表生成。所有表格文本，包括 `= + - @` 开头或控制字符、外链样式，必须作为安全文本写入，不执行公式/宏/网络请求。

错误状态：`INVALID_FORMAT`（非白名单/伪装格式）、`EMPTY_MEETING`、`INVALID_PREVIOUS_SCHEMA`、`DUPLICATE_TASK_ID`、`CORRUPT_INPUT`、`INVALID_DATE`、`AMBIGUOUS_MATCH`（可解析但对象待确认，不得错误归并）、`CONFLICT`（可解析但字段待确认，保留候选）、`OUTPUT_FAILED`（磁盘/依赖失败）。前六项及 OUTPUT_FAILED 不提交半成品或覆盖现有输出；冲突/歧义属成功但待确认且表格明确写出。输出先写临时文件、完整重新读取验证四表及关键字段后原子替换；旧输入永不写入。文件安全检查拒绝超限大小/解压炸弹、损坏 DOCX/XLSX、恶意路径或不可信外部引用；具体阈值由实现配置公开且测试，不能无限制加载。失败返回明确代码、文件及安全的原因和可行恢复提示，不能泄露全部原始会议内容。
